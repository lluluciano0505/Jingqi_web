1a:Tc79,<p>UrbanRhythm is a multi-agent AI pipeline that autonomously discovers, scrapes, judges, and semantically indexes cultural events across any US city. A Philadelphia case study indexed <strong>253 events from 40+ venues</strong> — libraries, museums, and galleries — at a cost of ~$0.75 per city run, with no hardcoded scraping logic.</p>
<p><strong>Architecture</strong></p>
<p>The system runs on a LangGraph StateGraph DAG with a Send API for parallel fan-out, processing up to 8 venues simultaneously.</p>
<p><strong>Agent 1 — City Resolver:</strong> Converts free-text city input ("Austin TX") into structured coordinates via Nominatim, selecting the most populous match for ambiguous names.</p>
<p><strong>Agent 2 — Venue Discovery:</strong> Queries OpenStreetMap Overpass API within a 30km radius to return libraries, museums, galleries, and arts centres — with name, address, website URL, OSM ID, and venue type. An Austin TX run returned 87 venues.</p>
<p><strong>Agent 3 — Scraper (3-Path ReAct):</strong> Each venue runs through a cost-prioritized cascade:</p>
<ul>
<li><em>Path A (Fast / GPT-4o-mini):</em> 8-tool ReAct loop — tries iCal feed detection, JSON-LD extraction, <code>/events</code> path navigation, and Jina Reader HTML-to-markdown before falling back. 30s timeout, 3–5s processing. 60–70% success rate.</li>
<li><em>Path B (Thorough):</em> Triggered when Path A finds fewer than 3 events. A 3-step sequential pipeline — Navigator reads the homepage and produces a <code>SiteProfile</code> (CMS type, depth, 5 candidate event links); Strategy Agent ranks targets; Extractor runs 3 parallel mini-ReAct workers with 4-call limits each. 90s timeout, 8–15s, 80–90% success rate.</li>
<li><em>Path C (Web Search / Tavily):</em> Fallback when both paths fail. 95%+ success rate, 5–10s.</li>
</ul>
<p><strong>Agent 4 — Playbook Store:</strong> A cross-run SQLite memory system keyed by domain. Records successful extraction strategy, CMS type, success/failure counts, and timestamps. On repeat runs, venue scraping skips trial-and-error by looking up known strategies — exact domain match → CMS pattern match → default fallback.</p>
<p><strong>Agent 5 — Judge:</strong> Rule-based scoring applied to every event: valid future date (+0.35), meaningful title (+0.25), location info (+0.20), description or URL (+0.20). Score ≥ 0.65 → accept; 0.40–0.64 → escalated to Claude 3.5 Sonnet for final verdict; &#x3C; 0.40 → reject. Roughly 50 borderline events per city run reach Sonnet, reducing inference cost ~4×.</p>
<p><strong>Agent 6 — Knowledge Graph:</strong> Post-processing semantic layer. Generates weighted venue tags (jazz, children, film, history), extracts entity names (artists, exhibition titles, recurring series), and computes venue-to-venue cosine similarity scores for recommendation.</p>

1b:Tcb6,<p>UrbanRhythm 是一套多智能体 AI 管线，可自主发现、抓取、评判并语义索引任意美国城市的文化活动。以费城为案例，系统覆盖图书馆、博物馆、艺廊等 <strong>40余家场馆，共索引253项活动</strong>，每次城市运行成本约 $0.75，全程无需任何硬编码抓取逻辑。</p>
<p><strong>系统架构</strong></p>
<p>系统基于 LangGraph StateGraph DAG，通过 Send API 实现并行扇出，最多同时处理8个场馆。</p>
<p><strong>智能体 1 — 城市解析器：</strong> 将自由文本输入（如 "Austin TX"）通过 Nominatim 转化为结构化坐标，模糊地名取人口最多的匹配项。</p>
<p><strong>智能体 2 — 场馆发现：</strong> 在30km半径内查询 OpenStreetMap Overpass API，返回图书馆、博物馆、艺廊和艺术中心的名称、地址、网站URL、OSM ID 和场馆类型。Austin TX 案例共发现87家场馆。</p>
<p><strong>智能体 3 — 抓取器（三路 ReAct）：</strong> 每个场馆按成本优先顺序依次尝试三条路径：</p>
<ul>
<li><em>路径 A（快速 / GPT-4o-mini）：</em> 8工具 ReAct 循环——依次尝试 iCal 订阅源检测、JSON-LD 抽取、<code>/events</code> 路径导航，再通过 Jina Reader 将 HTML 转为 Markdown 处理。超时30秒，耗时3–5秒，成功率60–70%。</li>
<li><em>路径 B（精细抓取）：</em> 当路径A找到不足3个活动时触发。三步顺序管线——Navigator 读取主页并生成 <code>SiteProfile</code>（CMS类型、页面深度、5个候选活动链接）；Strategy Agent 对目标链接排序；Extractor 用3个并行mini-ReAct worker（每个最多4次调用）执行抽取。超时90秒，耗时8–15秒，成功率80–90%。</li>
<li><em>路径 C（网页搜索 / Tavily）：</em> 两路均失败时的兜底方案。成功率95%以上，耗时5–10秒。</li>
</ul>
<p><strong>智能体 4 — Playbook 记忆库：</strong> 以域名为键的跨次运行 SQLite 记忆系统。记录每个场馆成功的抓取策略、CMS类型、成/失败次数及时间戳。重复运行时直接查表跳过试错——精确域名匹配 → CMS模式匹配 → 默认回退，大幅降低重复成本。</p>
<p><strong>智能体 5 — 裁判：</strong> 对每条活动进行规则评分：有效未来日期（+0.35）、有意义的标题（+0.25）、包含地点信息（+0.20）、有描述或链接（+0.20）。得分 ≥ 0.65 → 接受；0.40–0.64 → 升级至 Claude 3.5 Sonnet 裁定；&#x3C; 0.40 → 拒绝。每次城市运行约50条边界活动会进入 Sonnet，推理成本降低约4倍。</p>
<p><strong>智能体 6 — 知识图谱：</strong> 后处理语义层。生成加权场馆标签（爵士、儿童、电影、历史），提取实体名称（艺术家、展览标题、常设系列），并基于余弦相似度计算场馆间相似度评分，用于推荐。</p>
